Build notes (not part of the screen)

Why
Readiness only knows the last drill this device hosted (getLastDrill(), OwnerReadiness.jsx:15). The “Last month vs today” bars use the hard-coded PREVIOUS_DRILL sample (content.js:93). Nothing shows which drills the team has never practised.
Contract change
e.g. GET /drills?status=finished → { drills: [{ code, scenario_id, title, finished_at, results }] }. drills/engine.py already keeps finished drills until a Reset; this route only reads them.
Until then
A device-only version can list the drills this browser joined (player ids in session.js), read each with GET /drills/{code}?player_id=, and skip ones a Reset removed (404).
Data per row
results.team for the score, players[].missed_actions run through ACTION_LABEL for the habits, and SCENARIOS for the five drills and their lengths. The practice-attack note comes from GET /status.
Replaces
PREVIOUS_DRILL in Readiness, drill Results and the staff results screen. Keep the “sample data” label until real runs exist.

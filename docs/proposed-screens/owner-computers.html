Build notes (not part of the screen)

Why
The device strip on Right now shows a short name and a status pill. The API also returns each computer's location and services (GET /clinic) and its block, status time and impact (GET /devices), but no screen shows them. The owner can't see what stops when a computer goes down.
Data
  • GET /clinic → devices[]: agent_name, location, services.
  • GET /devices (flag ACTIONS): status, status_changed_at, block, impact. With ACTIONS off, fall back to derive.deviceStates(), as Right now does.
  • “Today” per computer: owner alerts and GET /actions filtered by agent_name.
Needs fields (optional)
“Plan B” is when_down and the protected addresses are never_block. Both are already in seed/clinic.json (drills use when_down) but neither is in ClinicResponse. Adding them is a contract change. Build the page without them first.
Links
Rows in Right now's “Computers” list open this page at the computer (#file-server). Mission control stays read-only.
Reuse
StatusPill, deviceName / deviceShort, DEVICE_STATUS from content.js.

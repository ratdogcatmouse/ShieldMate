Build notes (not part of the screen)

Why
Three of the five drills (the doctor's email phishing, the fake tech-support call and the supplier bank fraud) start with something a person notices first. Today a report can only come from a Wazuh alert, so staff have no way to raise one.
Guidance
Static, one set of steps per choice, reusing the drills' habits (ACTION_LABEL: VERIFY_BY_CALLBACK, PRESERVE_EVIDENCE, ISOLATE_NETWORK, CHANGE_PASSWORD, STOP_PAYMENT, REPORT_1930). Screens 1 and 2 can ship before the route; until then the last button says to tell Dr. Rao in person.
Contract change
e.g. POST /reports { staff_id, kind, note }, where kind is one of the five choices. It creates an owner notification (NotificationOut, kind "info", from_staff set), which shows on Right now and the phone alert preview.
Privacy and safety
The event log records the kind only, never the note (CLAUDE.md: event payloads never hold free text). The note is staff-typed text: render it as a text node on the owner's screen.
Open
Should a report open a full incident (alert row and IT loop), or stay a note? A note is enough to start.
